# キメメシ（仮）

なにも考えなくていい。**4回タップで、今日の一軒が決まる。**

デート・友達との飲み・幹事・ひとり飯 — その日の気分と価格帯・雰囲気・用途を4択で選ぶだけで、お店を1軒言い切りで提案するWebアプリのプロトタイプ。

## 使い方

- `index.html` をブラウザで開くだけで動きます（デモデータ内蔵・インストール不要）
- ホーム画面下のバッジをタップして[ホットペッパーAPIキー](https://webservice.recruit.co.jp/)（無料）を設定すると、現在地周辺の実在店舗の検索に切り替わります

## 構成

| ファイル | 内容 |
|---|---|
| `index.html` | アプリ本体（単一ファイル・依存なし） |
| `DESIGN.md` | 設計書：質問ツリー、ホットペッパーAPI対応表、決定エンジン仕様 |

## 実店舗データについて

店舗データは **GitHub Actions（サーバー側）が毎日ホットペッパーAPIから取得**し、`data/<エリア>.json` として保存しています。アプリはこのファイルを読むだけなので、ブラウザからAPIを直接叩きません。

- APIキーはリポジトリのSecrets（`HOTPEPPER_KEY`）に置くため、閲覧者には見えません
- CORSやプロキシの設定が一切不要で、表示も高速です
- 手動更新：Actionsタブ →「店舗データ更新」→ Run workflow

### セットアップ（初回のみ）

1. リポジトリの Settings → Secrets and variables → Actions → New repository secret
2. Name に `HOTPEPPER_KEY`、Secret にホットペッパーAPIキーを入れて保存
3. Actionsタブから「店舗データ更新」を手動実行

## 補足：ブラウザから直接APIを使う方法（上級者向け）

上の方式を使う場合は不要です。ホットペッパーAPIはブラウザからの直接呼び出し（CORS）に対応しておらず、端末・回線によっては検索が失敗します。どうしてもリアルタイム検索にしたい場合は、`proxy/Code.gs` を自分のGoogleアカウントで公開すると確実に動作し、APIキーも外部から見えなくなります。設置手順はそのファイルの冒頭コメントに書いてあります（無料・5分）。

発行された `https://script.google.com/macros/s/…/exec` のURLを、アプリのホーム画面下のバッジから設定してください（APIキーの代わりにURLを入れます）。

設定するとその場で接続テストが走り、どの経路で通ったか／どこで失敗したかが画面に表示されます。ホームの「接続テストを実行」からいつでも再確認できます。
